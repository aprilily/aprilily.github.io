발생 문제 및 해결 방법

  1. 한 언어 기준으로 만든 문제 테이블로는 3개 언어를 담을 수 없었습니다

    문제문제와 언어별 문장이 한 테이블에 묶여 있어, 언어를 추가하면 같은 문제가 언어 수만큼 복사되고 수정할 때마다 어긋날 수 있었습니다.

    해결문제의 공통 정보(quiz_content)와 언어별 내용(quiz_detail)을 분리하고, 조회 시 언어로 필터링하도록 바꿨습니다. 기존 108문제를 90문제 × 3개 언어 구조로 옮길 때는 시드 파일에 없던 힌트 데이터를 실제 DB에서 먼저 회수한 뒤 행 수를 대조해 검증했습니다.

    관련 커밋 : 7185564 다국어 퀴즈 지원 위해 quiz_detail/quiz_content 분리 · ea89dea EN/JA/ZH JSON 파일 DB 추가

  2. 문제 데이터를 다시 넣을 때마다 중복이 생길 수 있었습니다

    문제영어·일본어·중국어로 나뉜 JSON 문제 파일을 손으로 SQL로 옮기면 실수가 생기고, 같은 파일을 두 번 넣으면 문제가 중복 저장됩니다.

    해결JSON을 SQL로 변환하는 Python 스크립트를 만들어 중복 41건과 형식이 잘못된 1건을 걸러내고 컴피티션 문제 714개를 적재했습니다. ON DUPLICATE KEY UPDATE로 여러 번 실행해도 결과가 같게 만들어, 문제를 고친 뒤 다시 적재해도 데이터가 늘어나지 않게 했습니다.

  3. 요청이 동시에 들어오면 포인트가 음수가 되거나 보상이 두 번 지급될 수 있었습니다

    문제잔액을 먼저 조회하고 나중에 차감하는 구조라, 같은 요청이 거의 동시에 두 번 들어오면 둘 다 잔액 검사를 통과할 수 있었습니다.

    해결잔액이 충분할 때만 차감하는 조건부 UPDATE로 검사와 차감을 한 번에 처리하고, 영향받은 행이 0이면 잔액 부족으로 거절했습니다. 차감 · 해금 기록 · 포인트 이력 저장은 하나의 트랜잭션으로 묶었고, 첫 풀이 보너스도 bonusAwarded = false 조건으로 한 번만 지급되게 했습니다.

    @Modifying
@Query("UPDATE UserAsset ua SET ua.currentPoints = ua.currentPoints - :points " +
       "WHERE ua.user.userId = :userId AND ua.currentPoints >= :points")
int tryDeductPoints(Long userId, int points);   // 0이면 잔액 부족

    관련 커밋 : 6740a40 해금 스토리 언어별 구분 추가 · 2b061a4 포인트 로직 수정

  4. 콘텐츠 해금 상태가 언어와 관계없이 똑같이 조회되었습니다

    문제영어로 해금한 스토리가 일본어·중국어에서도 해금된 것으로 보였습니다. 서비스 로직만 고쳐서는 해결되지 않았습니다.

    해결조회 쿼리까지 따라가 보니 JOIN 조건에 언어 구분이 빠져 있었습니다. 해금 기록에 언어를 추가하고, 조회와 해금 모두 언어 조건을 넣었습니다. 학습을 시작하지 않은 언어는 해금할 수 없도록 먼저 검증하게 했습니다. 이후로는 조건을 바꿀 때 연관 쿼리의 영향 범위까지 함께 점검하고 있습니다.

    관련 커밋 : 6740a40 해금 스토리 언어별 구분 추가 · ee604db 스토리 해금 기능 수정

  5. 봇 컴피티션 결과가 다른 매치에 반영될 수 있었습니다

    문제결과 저장과 일시정지 처리에서 사용자의 진행 중 매치 목록 중 첫 번째를 가져오고 있어, 진행 중인 매치가 여러 개면 엉뚱한 매치에 결과와 보상이 반영될 수 있었습니다.

    해결요청에 매치 ID를 받아 matchId + userId로 정확히 조회하고, 이미 끝난 매치는 처리하지 않도록 상태를 검증했습니다. 보상은 봇보다 라운드를 더 많이 이겼을 때만 지급하도록 바꿨습니다.

    관련 커밋 : 82a5e4b 봇컴피티션 포인트 로직 수정 · a48b7b0 봇 컴피티션 로직 수정

  6. 일본어·중국어 데이터가 DB에 넣는 과정에서 깨졌습니다

    문제SQL 파일을 반영하는 접속 환경의 문자셋이 달라, 일본어·중국어 문장이 깨진 채 저장되었습니다.

    해결원인이 접속 문자셋 차이임을 확인하고 utf8mb4로 다시 반영해 데이터를 복구했습니다. 덤프 파일을 만드는 방식도 바꿔 같은 문제가 반복되지 않게 했습니다. 운영 데이터를 바꿀 때는 임시 테이블에 먼저 반영하고 검증 쿼리로 확인한 뒤에만 확정했습니다.

    관련 커밋 : 0fd6bf9 봇 컴피티션 인코딩 문제 수정 · 5e9f87e 해금 스토리 인코딩 문제 수정

  7. 스토리 오답과 컴피티션 오답이 따로 관리되었습니다

    해결날짜를 기준으로 두 데이터를 병합하고, 뉴스가 없는 날은 직전 값으로 채워 시계열을 이어지게 정리했습니다.

  2. 로컬에서만 열리는 대시보드를 다른 사람에게 보여줘야 했습니다

    해결Streamlit으로 띄운 대시보드를 ngrok으로 외부 주소에 연결해, 별도 서버 없이 발표와 피드백에 사용했습니다.

  3. 보완할 점

    주가와 예측 값은 샘플 데이터로 화면을 먼저 구성했습니다. 실제 주가 데이터 연동과 예측 모델 적용이 다음 단계입니다.

  • 문의 서버 : Node.js(Express) · MongoDB(Mongoose)로 문의 등록 · 목록 · 상세 · 답변 · 삭제 REST API

  • 관리자 문의 화면, 설정 · 로그인 화면

발생 문제 및 해결 방법

  1. 곡을 바꿀 때 이전 음원이 정리되지 않으면 소리가 겹칠 수 있었습니다

    해결새 곡을 불러오기 전에 이전 음원을 unloadAsync()로 메모리에서 해제하고, 재생 상태 콜백에서 로딩이 끝났는지(isLoaded) 확인한 뒤에만 재생 시간과 상태를 화면에 반영했습니다.

    관련 커밋 : 9a63189 update musicplayer · e4c6d35 playlistupdate

  2. 한 곡 재생과 재생목록 재생이 섞였습니다

    문제재생목록을 듣다가 다른 곡 하나를 누르면, 그 곡이 끝난 뒤 이전 재생목록이 이어서 재생될 수 있었습니다.

    해결실제 재생 함수를 내부용으로 분리하고, 한 곡 재생은 대기열을 비운 뒤 재생하도록 나눴습니다. 재생목록은 곡이 끝나면 다음 곡을 자동으로 재생합니다.

    관련 커밋 : ef756ad soundplaylist 재생목록 완료

  3. 문의 저장에 실패해도 첨부 이미지는 서버에 남았습니다

    문제파일은 저장 전에 먼저 업로드되기 때문에, 문의 데이터 저장이 실패하면 주인 없는 파일이 쌓였습니다.

    해결저장에 실패하면 이번 요청에서 올라온 파일을 삭제하고, 문의를 삭제할 때도 첨부 파일을 함께 지웠습니다. 이미지 형식 · 10MB · 최대 5개로 업로드를 제한하고, 제한을 넘으면 이유가 담긴 400 응답을 돌려주도록 에러 처리를 모았습니다.

    관련 커밋 : 9e3d1a4 updateinquiryfileimage · 71e44fd 문의사항 서버 완성

  4. 꿈 감정 분석 응답이 늦어 앱이 타임아웃되었습니다

    해결외부 자연어 분석 API 연동을 준비했지만, 시연에서 응답 지연으로 앱이 멈추지 않도록 서버에서 키워드로 긍정 · 중립 · 부정을 판별해 바로 응답하게 바꿨습니다.

    관련 커밋 : e453af4 꿈 ai 추가

  5. 시연 장소인 교내 와이파이에서만 서버에 연결되지 않았습니다

    해결집 네트워크에서는 정상이라 네트워크 차이를 의심했고, 교수님께 여쭤 교내 방화벽이 원인일 가능성을 확인했습니다. 핫스팟으로 서버와 기기를 같은 네트워크에 연결해 시연을 마쳤습니다.
